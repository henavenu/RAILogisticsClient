Built-in Engine Rules These rules are implemented in code and cannot be changed via PAP.
MRA Rule 1 Verdict Escalation

A single COERCIVE dimension score produces a COERCIVE verdict for the entire request. NORMATIVE is returned only when at least one dimension is normative and none are coercive.

MRA Rule 2 Violation Priority Ordering

When multiple dimensions are non-permissive, violations are ordered by verdict level (COERCIVE first) then by severity. This determines which violation and remediation message appears first in the response — it does not change the final verdict.

MRA Rule 3 All Violations Reported

Every dimension that exceeds its permissive threshold is included in the response. Nothing is silently dropped, even when the overall verdict has already been determined by another dimension.

MRA Rule 4 Policy Thresholds Are Authoritative

Verdicts are determined solely by the policy thresholds configured in the Policies tab. Raw scores returned by the Guardrail Service are inputs only — they do not directly determine the verdict. If a provider returns no score, that dimension is excluded from synthesis.

MRA Rule 5 Deferred Dimensions Are Excluded

Dimensions marked deferred in the Guardrail Service are scored but never contribute to violations or verdicts. Use this to register a new dimension and monitor its scores before activating enforcement.

Session Rule 1 Worst-Score Accumulation

The Policy Engine retains the highest score seen per dimension across all turns in a session. A subsequent clean message cannot reduce a previously elevated score — risk signals only accumulate.

Session Rule 2 Per-Turn Verdict Is Always Returned

The verdict returned to the application always reflects the current turn only. Session-level escalation patterns are recorded in the audit trail for observability but do not modify the verdict. Applications do not need to interpret session state.

Session Rule 3 Session Composite Score

The session trust score aggregates per-dimension safety values derived from worst-case scores seen across all turns. Score starts at 1.0 (fully trusted) and trends toward 0.0 (maximum risk) as violations accumulate. See the Formulae & Scoring Models reference below for the exact expressions.

Trust Accountability Model per-agent platform score

Controls which COERCIVE verdict roles degrade the per-agent Platform Accountability Score (shown in the Agent Activity table above). A weight of 1.0 = this role is a platform fault — the agent's trust score degrades. 0.0 = user fault — no penalty to the agent.

user_prompt no penalty
User's raw input. Adversarial prompts are user-fault — the agent is a governance victim, not the cause.
agent_to_agent full penalty
A2A handoff evaluation. A compromised routing decision reflects on the originating agent's design.
llm_response full penalty
LLM output evaluation. PII leakage or toxic content in a response is fully attributable to the platform.
tool_call full penalty
Tool invocation evaluation. An agent attempting a blocked action (e.g. unsanctioned transfer) is platform fault.
Formula: score = 1.0 − Σ(violations_by_role[r] × weight[r]) / max(1, evaluations) · Weights take effect immediately on the next Agent Activity refresh.
